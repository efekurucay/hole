# Contributing to Hole

Build with `./scripts/build.sh` and run `build/Hole.app/Contents/MacOS/Hole --self-test` before opening a pull request. For changes to file handling, use a temporary fixture and describe the expected effect on each selected path. Exercise both success and refusal paths without touching personal data.

Include your macOS version and CPU architecture in bug reports. Redact user names, private paths, and package names from screenshots or logs as needed. For security issues that affect file selection or Trash boundaries, use [GitHub private vulnerability reporting](https://github.com/efekurucay/hole/security/advisories/new).
